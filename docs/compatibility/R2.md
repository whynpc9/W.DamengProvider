# 异步操作、取消与超时

本文说明当前 [0.3.1](../release-0.3.1.md) 的异步和取消行为。数据源及流式 LOB 见[数据源与 LOB](R3.md)。

## 真正的异步网络调用

Open、Prepare、Execute、Read、NextResult 的异步入口贯通异步网络 I/O，不使用 `Task.Run` 包装同步调用，也不回退到 ADO.NET 基类的同步实现。已有缓存时，操作可以立即完成。

BLOB/CLOB 支持异步物化和流式读写；`GetSchemaAsync` 使用异步目录查询，`GetSchemaTableAsync` 只读取本地缓存。数组绑定、`DbBatch` 和存储过程分别遵循各自的专项说明。

## 取消与 Reader 生命周期

- 取消令牌只对本次调用有效。`ExecuteReader` 成功返回后，执行阶段的令牌会解绑；后续 `Read` 使用新的调用令牌。
- `Command.Cancel` 取消当前执行或 Reader；没有活动操作时不做任何事。旧命令身份不能取消新的执行。
- 即使连接失效后 `Reader.IsClosed` 已变为 `true`，仍必须调用 `Close`/`Dispose`，释放连接租用和命令资源。
- 发送前取消或超时不会产生网络副作用，连接、活动事务和已准备句柄保持可用。
- 发送后取消或超时会中止物理会话，连接进入 `Broken`。驱动不会自动重连、重放请求或将连接放回池中。

## 超时的计算方式

- **连接**：DNS、TCP、STARTUP、LOGIN 和初始化共用一份总时限。
- **命令**：每次公开 Execute/Reader 调用使用一份固定时限；内部 Fetch、分块和 heartbeat 不会重置它。
- **清理**：使用独立且有限的 `CleanupTimeout`。
- **事务**：BEGIN 的配置、清理和激活阶段分别记录失败位置；已发送 BEGIN 后再失败，事务结果可能为 `OutcomeUnknown`。

提交请求已发送但结果无法确认时，`OutcomeUnknown` 优先于其他状态。调用方应通过新连接核对业务结果，不要盲目重试。

## 公开错误分类

| 错误类型 | `ErrorKind` / 错误码 | 含义 |
| --- | --- | --- |
| `DmTimeoutException` | `Timeout` / `WDM_TIMEOUT` | 当前报告总时限到期；`IdleTimeout` 枚举保留但本版本不报告 |
| `DmOperationCanceledException` | `Canceled` / `WDM_CANCELED` | 用户令牌或 `Command.Cancel` 取消，保留首个取消原因 |
| `DmCommitOutcomeUnknownException` | `OutcomeUnknown` / `WDM_COMMIT_UNKNOWN` | 提交结果未确认，连接不可复用 |
| `DmException` | `Transport` / `WDM_TRANSPORT` | 网络或 TLS 传输失败，包含实际失败阶段和原 socket 异常 |

`FailureInfo` 只包含稳定的错误分类、失败阶段、操作或事务结果、连接是否可复用，以及确实存在的服务器错误号；不包含 SQL、参数值、连接串或认证报文。

`OperationOutcome` 描述失败子阶段是否已发送请求。`TransactionOutcome` 描述整个事务是否仍可能处于未知状态，两者不能混用。

## 目标框架差异

`netstandard2.1` 不支持 TLS 和 `DbBatch`，其他差异见[旧目标框架说明](core31.md)。
