# 基础兼容与行为变化

当前版本为 [0.3.1](../release-0.3.1.md)。包和程序集名为 `W.DamengProvider`，公开命名空间为 `W.Dm`，产品项目不依赖 EF。

从 `DM.DmProvider` 或旧 `W.DmProvider` 迁移时，必须更新引用并重新编译，不能只替换 DLL。

## 默认支持边界

- 现代目标框架默认要求完整 TLS，并验证证书。
- 支持异步操作、连接容量管理和流式 LOB，具体见[异步与取消](R2.md)及[数据源与 LOB](R3.md)。
- 不提供自动重连、请求重放、分布式事务或原生批量装载。
- 各项服务器能力按具体版本、协议和编码组合验证，不从单一服务器或 EF 测试套件推导普遍兼容性。

## 重要行为说明

### SQL、参数与 NULL

SQL 参数和事务保护逻辑使用非嵌套块注释语法，不会把第二个语句隐藏在注释深度计数中。

整数类型的显式 getter 遇到 SQL NULL 时会报转换错误，真实零值不受影响；`GetValue`、`GetFieldValue<object>` 和 `GetFieldValue<DBNull>` 仍返回 `DBNull`。包括 `GetGuid` 和 `GetFieldValue<T>` 在内的显式 NULL 转换使用 `DmException` 6081。

### LOB 大小限制

完整物化读取的返回载荷上限为 **64 MiB（67,108,864 字节）**：

- BLOB `byte[]` 按字节数计算。
- CLOB `string` 按 UTF-16 载荷字节数计算，即字符数的 2 倍。
- BLOB 十六进制字符串按输入字节数的 4 倍计算。

已知超限会在读取或分配前拒绝，不会静默截断。这是单个值的大小限制，不是进程总内存上限。CLOB 使用空缓冲区探测长度时，返回解码后的 UTF-16 长度，且不消耗顺序读取位置。流式读取见[数据源与 LOB](R3.md)。

### 更换命令连接

将 `DmCommand.Connection` 设为 `null` 会清除该命令的连接和语句状态。以下情况会立即失败并保留原绑定：

- 命令正在执行或仍有活动 Reader。
- `command.Transaction` 仍指向活动事务。
- 原物理会话正被其他操作使用。

调用方可以先清除 `command.Transaction`；事务对象仍由原连接管理。重新绑定连接后会重新准备语句，不复用旧连接的句柄。

### 保存点与直接 SQL

在已验证的服务器环境中，显式本地事务可以使用受支持的单条保存点 SQL。ADO.NET API 和直接 SQL 共用同一保存点栈，SQL 原文不会被改写。

驱动保留 `WSP_` 前缀供内部保存点使用，用户 SQL 不得触及该前缀。大小写或引号含义不明确、无法确认回滚目标时，驱动会保守清空跟踪状态，避免继续使用失效保存点。总保存点跟踪栈和 API 序号均以 128 为限；完整 `COMMIT`/`ROLLBACK`、参数化或复合事务控制语句仍应使用标准事务 API。详见[事务](T10-transactions.md)和[隔离级别与保存点](T11-isolation.md)。

## 目标框架差异

`netstandard2.1` 不支持 TLS、`DbBatch`、DateOnly/TimeOnly 映射；现代四个目标框架保持完整能力。详见[旧目标框架说明](core31.md)。
