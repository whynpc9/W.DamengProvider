# 数据源、流式 LOB 与故障兼容范围

当前版本为 `0.2.0`；本页历史阶段证据仍归原候选，当前发布状态与验证范围见[发布记录](../release-0.2.0.md)。

本页描述当前源码的数据源与流式 LOB 行为；正式发布验证范围见发布记录，机器状态见 [progress.json](../implementation/progress.json)。

| 能力 | 当前范围 |
| --- | --- |
| DmDataSource / 直接 Pooling | 数据源独立容量 owner；直接池按完整配置/秘密隔离共享 bounded registry，默认 Pooling=false |
| 容量与等待 | MaxPoolSize 默认100，MaxPoolWaiters默认1024；creating/leased/closing占容量，FIFO等待和总 PoolAcquireTimeout |
| 物理复用 | reset未证实，所有归还会话销毁，实际复用率0；每租约重新认证，不宣称握手优化 |
| Clear / Dispose | 同容量域epoch退休；Clear不打断在借业务；Dispose终止新准入和等待者，在借业务可完成 |
| 显式TLS证书文件 | 直接DmConnection Pooling=true拒绝；使用独立DmDataSource。证书轮换后重建数据源，证书字节不宣称原子快照 |
| 输出LOB | lazy forward-only GetStream/GetTextReader；当前row/execution/transaction生命周期；单活动flow、顺序守卫 |
| 范围读取 | BLOB GetBytes有界；CLOB GetChars按CLR UTF-16扫描/偏移，wire Data.len保持opaque，不猜字符单位 |
| 输入LOB | 显式Blob Stream或Clob TextReader且Input；caller-owned未知长度/不可seek源，async分块，无重放/rewind/dispose |
| 完整物化 | 64MiB返回payload上限保留；CLOB GetBytes仍是编码字节完整物化兼容接口 |
| NCLOB / ROWID | 两已测profile的NCLOB折为TEXT/CLOB同servercodec，不宣称独立national codec；ROWID GetChars本地rendered，GetTextReader拒绝 |
| 诊断 | ActivitySource/Meter 的稳定诊断标识为 `W.DmProvider`；bounded后台export，固定enum/numeric标签；无SQL/values/credentials/baggage/traceState，累计计数独立于可丢队列 |
| 事务和故障 | 已确认提交/回滚诊断success；sent未确认OutcomeUnknown，不重试；一般服务器错误号保留但保守Broken。2026-10-13 起，仅 8.1.5.60 profile 下实测为语句级的错误号（见 [服务器错误恢复](server-error-recovery.md)）在本事务 Active 或无本地事务的 autocommit 下保留会话，其余仍 Broken |
| 0.2.0 新增能力 | 数组绑定/DbBatch 见 [I07/I08](I07-I08-array-binding-dbbatch.md)，异步 GetSchema 见 [I10](I10-metadata.md)，存储过程/输出游标见 [I09](I09-stored-procedures.md) |
| 不支持 | statement pooling、未经验证的 session reset、物理会话复用及未知 native 互操作 |

## 验证范围

已表征环境为 shared DM 8.1.5.60 / UTF-8 / 显式 PlaintextAllowed，以及隔离 TLS DM 8.1.4.6 / GB18030。profile 的时间、隔离级别与保存点能力分别判断，不能由 TLS 连接成功推导全部能力。其他 OS/RID、服务器版本、长期压力和完整下游 EF 兼容需另行验证；正式包的实际证据见[发布记录](../release-0.2.0.md)。

2026-10-15 补充的当前源码 Windows / win-x64 / .NET 10.0.9 验证见 [issue #11 Windows 记录](I11-windows.md)：DM 8.1.5.60、UTF-8、消息协议 21、显式明文。该支持单元与 macOS/TLS 的历史记录分别列证，不追溯扩大已发布包范围；Windows TLS loopback 的证书验证与 mTLS 也不能代替远程达梦 TLS 实库。

本机无 CRL 的测试 CA 显式选择 NoCheck，产品默认 Online 不变。真实测试只使用 WDM_PROVIDER_TEST，精确清理本轮对象并由新连接确认最终状态。历史阶段的固定候选、测试计数与宿主预算不作为当前开发流程。

2026-10-15 源码 `24e792d` 在 Ubuntu 24.04 WSL2 / linux-x64 / .NET 10.0.12 完成十二套离线测试及本地包消费验证；Linux 实库与当前候选长时资源检查仍 pending，见 [issue #11 Linux 记录](I11-linux-validation.md)。

当前源码另提供 .NET 8/9/10 三目标构建与发布消费矩阵，见 [issue #12 多目标记录](I12-multitarget.md)。该记录分别标明运行时离线验证与未完成的实库验收，不扩大上述历史服务器证据。

回退时pin明确旧候选、关闭直接Pooling并释放数据源/重建连接。OutcomeUnknown交由应用核对已发生效果，不能盲重试。

发布验证应确认实际包与受测程序集；构建与来源配置以当前项目和发布说明为准。第三方归属与 native 许可边界见 [THIRD-PARTY-NOTICES.md](../../THIRD-PARTY-NOTICES.md)。
