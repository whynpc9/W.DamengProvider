# 数据源、流式 LOB 与故障处理

本文说明当前 [0.3.1](../release-0.3.1.md) 的数据源、连接容量、LOB 和诊断行为。

## 数据源与连接容量

| 功能 | 当前行为 |
| --- | --- |
| `DmDataSource` / 直接池化 | 每个数据源独立管理容量；直接池按完整配置和秘密隔离。`Pooling` 默认值为 `false`。 |
| 容量与等待 | `MaxPoolSize` 默认 100，`MaxPoolWaiters` 默认 1024。创建中、已租用和关闭中的会话都占容量；等待者按 FIFO 处理，并共用 `PoolAcquireTimeout`。 |
| 物理连接复用 | **当前不复用。** 每次租用都新建并认证物理会话，归还时销毁，因此没有连接复用的性能收益。 |
| `Clear` / `Dispose` | `Clear` 退休当前代际，不打断已租用连接；`Dispose` 停止新请求和等待者，已租用连接可以完成。 |
| 显式 TLS 证书文件 | 直接 `DmConnection` 使用 `Pooling=true` 时拒绝；请使用独立 `DmDataSource`。证书轮换后应重建数据源。 |

尚不支持语句池和未经验证的会话重置。连接复用调查见[性能基线与重置限制](I06-pool-reuse-baseline.md)。

## BLOB/CLOB 流式接口

| 场景 | 当前行为 |
| --- | --- |
| 输出 LOB | `GetStream` / `GetTextReader` 提供惰性、只进流式读取；生命周期绑定当前行、执行和事务。同一对象只允许一个活动流，并遵守顺序读取限制。 |
| 范围读取 | BLOB `GetBytes` 提供有界读取；CLOB `GetChars` 按 CLR UTF-16 字符计算偏移，不把协议字节长度当成字符数。 |
| 输入 LOB | 输入参数必须显式声明 BLOB `Stream` 或 CLOB `TextReader`。支持不可 seek、未知长度的调用方流，异步分块发送；驱动不回放、重置或释放调用方的流。 |
| 完整物化 | 返回载荷上限为 64 MiB。CLOB `GetBytes` 仍是完整物化的兼容接口。 |
| NCLOB / ROWID | 已验证环境中 NCLOB 按服务器现有编码作为 TEXT/CLOB 处理，不宣称独立国家字符集编解码；ROWID 的 `GetChars` 返回本地文本，`GetTextReader` 拒绝。 |

数组绑定和 `DbBatch` 见[批量执行说明](I07-I08-array-binding-dbbatch.md)。

## 诊断与故障

- `ActivitySource` 和 `Meter` 的稳定名称均为 `W.DmProvider`。
- 后台导出队列有容量上限；标签只使用固定枚举和数值，不包含 SQL、参数值、凭据、baggage 或 traceState。累计计数独立保留，即使导出队列丢弃项目也不受影响。
- 已确认提交或回滚记录成功；发送后结果未确认记录 `OutcomeUnknown`，驱动不自动重试。
- 一般服务器错误会保留错误号并保守关闭会话。只有在指定服务器环境、错误号和事务条件均满足时才保留会话，详见[服务器错误恢复](server-error-recovery.md)。

## 验证范围与限制

当前主要实库环境为：

- DM 8.1.5.60 / UTF-8 / message 21 / 显式 `PlaintextAllowed`。
- 隔离 TLS 实例 DM 8.1.4.6 / GB18030。

2026-10-15 的 Windows / win-x64 / .NET 10.0.9 验证明细见[Windows 记录](I11-windows.md)；Ubuntu 24.04 WSL2 的离线和包消费结果见[Linux 记录](I11-linux-validation.md)。这些结果分别属于各自环境，不能据此宣称其他操作系统、服务器版本、长期压力或完整下游 EF 已通过。

本机测试 CA 没有 CRL，因此对应测试显式使用 `NoCheck`；产品默认仍为 `Online`。实库测试只使用 `WDM_PROVIDER_TEST`，精确清理本轮对象，并由新连接确认最终状态。
