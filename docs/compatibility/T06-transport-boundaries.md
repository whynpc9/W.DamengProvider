# 网络传输与消息边界

本文说明连接期限、消息大小和传输失败行为。TLS 见[安全说明](T07-security.md)，取消和异步操作见[异步和取消](R2.md)。

## 连接与命令期限

- 建立连接使用一份单调时钟总预算，覆盖 DNS、多地址 TCP 尝试、STARTUP、LOGIN 和初始化。一次成功的 `Open` 不会先关闭 socket 再重新连接。
- Command 的执行期限覆盖本次消息循环。Reader 的后续公开调用各自获得预算，用户在两次调用之间的停顿不计入下一次 `Read`。
- 超时值 0 表示不限时；有限预算到期后，不会退化成 socket 的无限等待。

## 消息读取与大小限制

- Socket 发送会处理短写；接收先精确读取 64 字节头，再按核实后的长度读取正文。
- EOF、零进展、负长度、长度溢出、超限、校验失败和不支持的压缩模式都会明确拒绝。
- 单个总帧最多 **64 MiB**，这是驱动自身的保护值，不是服务端协议最大值，也不代表完整结果集的总内存上限。解码后的行、引用数组和 BDTA 值另受各自预算约束。
- Heartbeat 按完整帧消费并校验，共用原期限。当前 CMD=200 的头部 XOR 与协商后的正文 CRC 使用不同条件，字段依据见[帧布局记录](../implementation/T06-frame-layout.md)。
- `b` 的解码受实际有效长度限制；未支持的复杂类型描述符会明确拒绝，避免无界递归。

## 同步、异步与失败分类

同步入口使用同步网络调用，异步入口贯通异步网络 I/O。现代目标框架默认 `RequireTls` 并验证证书；未知原生加密或协商模式继续拒绝。

驱动自身的 socket/I/O 失败统一包装为传输错误，详见[失败分类说明](I16-ef-integration-feedback.md)。请求发送后，未确认的操作或提交不能视为可安全重试。
