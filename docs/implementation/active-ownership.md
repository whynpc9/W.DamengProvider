# 协作与并发约定

本文适用于共享工作区中的开发、代码审查和验证，不记录固定负责人或一次性授权。

- 开始修改前检查工作区状态，明确任务边界，保留其他人的未提交工作。
- 多人或多代理共享工作区时，先约定各自负责的文件和只读范围，避免交叉修改。同一文件需要交接时，先停止原写入者。
- 共用 `bin/obj` 的构建，以及会相互影响的数据库测试，应串行执行；可隔离的只读审查可以并行。
- 实现、代码审查和行为验证分别记录。条件允许时由不同执行者审查和验证；只能自行复查时，应明确说明，不称为独立审查。
- 验证期间保持受测源码稳定。修改后通知验证者，并重跑受影响的检查。
- 历史交接、模型或角色名称以及工具中的 approval 字段只解释原记录，不授予当前操作权限，也不新增审批步骤。

数据库和凭据边界按 [AGENTS.md](../../AGENTS.md) 执行。当前产品行为见[文档导航](README.md)，发布状态见 [progress.json](progress.json)，后续工作见[路线图](../roadmap.md)。
