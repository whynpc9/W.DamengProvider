## 2. 已实现的驱动改造

### 时间表示、转换和 wire 编解码

- 新增整数时间核心、不可变时间字段和原始 metadata 类型；以整数处理小数秒及 .NET 的 100ns tick 投影，避免边界计算中由浮点或隐式量化产生进位、截断。
- 明确七种 packed wire 布局及原 legacy 微秒布局的适配；纳秒字段与 CLR tick 转换经过精度和值域检查。
- 新增宽整数 interval 处理，并接入时间 helper、writer 和 reader。公开 helper 的单位与格式边界按签名逐项处理，保留既有 golden 回归。
- 对不能精确投影到 CLR tick 的值显式拒绝；精确文本读取仍保留高精度字段，不通过取整让 typed getter 成功。

主要新增文件位于 [Internal/Types](../../../src/W.DamengProvider/Internal/Types)：`DmTemporalInteger.cs`、`DmTemporalFields.cs`、`DmTemporalIntervalFields.cs`、`DmTemporalRawMetadata.cs`、`DmTemporalWireCodec.cs`、`DmTemporalLegacyAdapter.cs`、`DmTemporalCapabilityProfile.cs`。既有 `DmTemporalCodec.cs` 和相关 legacy 时间类型/工具也已接线。

### 参数绑定、能力与 Reader

- 时间参数使用 `Scale` 表示小数秒位数；时间参数 `Precision` 未设或 0 可用，显式非零值拒绝。decimal 的 Precision/Scale 不受此时间规则影响。
- 参数、Command plan、writer 消费同一冻结的 profile/target 与类型选择，覆盖有类型 NULL、默认及显式精度。
- Reader 使用不可变 descriptor，覆盖 typed/generic getter、精确文本、NULL、schema、同步/异步及相关读取恢复合同。
- 七位写入受实际服务器 profile 约束；并非所有达梦连接都开放七位。TIME/interval 七位写、八九位写、非 NULL 的 TLTZ 值等仍按既定边界关闭。
- 1582-10-05 至 1582-10-14 的写入保持保守拒绝；未知格式/未开放能力不自动推广支持。

产品接线涉及 `DmParameterBinding.cs`、`DmCommandPlan.cs`、`DmCommand.cs`、`DmParameter.cs`、`DmDataReader.cs`，以及 `DmField`、`DmGetValue`、`DmSetValue`、`DB2N`、`N2DB`、`DateUtil` 等 legacy 入口。

新增测试集中在 [TypeTests](../../../tests/W.DmProvider.TypeTests)、[AsyncTests](../../../tests/W.DmProvider.AsyncTests) 和 [时间向量](../../../tests/fixtures/temporal-native)。探针及验证工具位于 `tools/TemporalBoundaryProbe`、`TemporalWiringAcceptance`、`TemporalCandidateAcceptance`、`TemporalProfileDiagnostic` 和 `eng/temporal-precision*.py`。
