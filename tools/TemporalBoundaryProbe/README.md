# TP-01 temporal boundary characterization

New independent tool; it does not change the old TemporalPrecisionProbe or the provider. All dotnet and DB commands belong to the Low verification window after source freeze and review.

`TemporalBoundaryProbe.csproj` uses exact PackageReference for official O and one W version. O selects the fixed net9 asset; W selects net10. One process loads O and one W assembly; baseline and candidate W use separate runs/build directories. A manifest pins nupkg SHA, package asset SHA, loaded DLL SHA/MVID, and package version. Both NuGet assets and runtime deps must identify the real package asset. An existing loose DLL or ProjectReference cannot substitute for a package.

The committed identity separates `comparison_head` fe89bd44 from the archived v23 producer head 2b39fec0. The actual archived product source manifest SHA is `241e15b52b436a55fe3a299e777b281cee0d6b3c22782a0323de311e1d87d1d5`, matching the tracked v23 root readback; neither the original source nor package is rewritten. `identity.producer` binds source head, exact source-manifest SHA, optional source-archive SHA, W version/package SHA/DLL SHA/MVID. A source manifest must contain real normalized source-file paths and SHA entries including provider sources; a count is insufficient. `--source-archive` is required exactly when the producer records its hash. Both Python and the executable verify the byte identity chain. The executable also checks the package's actual nuspec ID/version and runtime deps asset. A rebuilt baseline uses a new unique package version and its own producer record; a future candidate uses `phase: candidate` and its own frozen source/package relation. The tool restores a package consumer and never rebuilds the provider.

Run from this checkout or a frozen copy, with a new output directory:

```sh
python3 eng/temporal-precision.py \
  --feed /absolute/verified-package-feed \
  --identities tools/TemporalBoundaryProbe/identities.json \
  --source-manifest /absolute/frozen-product-source-manifest.json \
  --repo /absolute/original-W.DamengProvider \
  --profile shared --output /absolute/new-evidence-directory
python3 eng/temporal-precision.validate.py /absolute/new-evidence-directory \
  --gate characterization --output /absolute/new-validation.json
```

The runner copies tool inputs into the output directory and restores/builds there with SDK 10.0.401, writable DOTNET_CLI_HOME, single node, no reusable/shared compiler/build servers. It restores from the explicitly supplied local package feed; packages' transitive dependencies must be available in that feed or the existing cache. Build environments remove inherited DAMENG variables. TEST credentials are loaded only by the original repository's wrapper immediately around the executable. Secrets are never copied. `--profile tls` selects the original TLS wrapper and existing local certificate paths, RequireTls with the explicitly approved local CA NoCheck revocation policy. It never turns off certificate validation. O TLS is closed because this tool has no verified strict official TLS configuration; O TLS is not claimed as accepted.

Three lanes run serially: `core`, `metadata`, `extended`. `--lanes` supports focused reruns, but the validator requires all three lanes from the same frozen run. `--deadline` defaults to 900 seconds per lane, bounded 60–1800. Every case checkpoints a safe JSON report. The runner discards native stdout/stderr rather than risking credentials in uncaught driver diagnostics; build/restore exit codes remain recorded. It stops on an infrastructure failure/deadline and preserves existing evidence. A successful process exit means complete characterization, not candidate correctness.

The core lane records DateTime min/min+1/max/max-1/max-9, ordinary tick and microsecond, century/leap/midnight, all DateTime kinds, six/seven fixed columns, ordinary offsets and ±14/-13/-12:59 limits, local/UTC endpoint domains, and DML rollback. DTO constructor failures are separate precondition observations and never treated as driver rejections. Each successful typed write is read using independent fresh O/W connections and server FF7/FF9 plus EXTRACT components. O Precision7 and W Scale7 paths are distinct. Official typed boundary failures are retained; they never become correctness expectations. Failed writes get an independent persisted-row count.

The metadata lane covers inferred DateTime/DateTimeOffset, DbType.DateTime/DateTime2/DateTimeOffset and both provider declarations, Scale unset/0/3/6/7/8/9/19/23/255 and Precision unset/0/7/9, fixed/advisory describe, NULL, value replacement, explicit metadata change and reprepare. Nonzero Precision also has fixed non-NULL and advisory NULL axes. Axes are covered separately to bound the matrix. `requested_precision` is the public DmParameter.Precision request; `observed width` is protocol width. They are separate fields. Valid initial/replacement/reprepare phases actually execute; fixed phases use a new rid parameter per INSERT and fresh readback, with actual column metadata separate from user scale. Before-execute and after-execute parameter snapshots are separately captured; raw describe provenance is not overwritten by effective selection. Advisory phases use SELECT parameter output plus independent server TO_CHAR, explicitly without claiming an EXTRACT oracle or persisted write. Runtime reflection records actual CType, width, semantic scale, mask and typeFlag. Old normalized metadata cannot reveal original raw flags: `raw_scale_status` explicitly says unobservable rather than guessing. Candidate capture is observed only when its dedicated raw metadata snapshot exists. Encoded scale is observed only from a real immutable TemporalBinding.EncodedScale/EncodingScale property; it is never inferred from the requested scale or column. The legacy package can record this as unobservable. The future candidate gate remains closed until TP-04 provides an observable binding snapshot.

The extended lane separately classifies server DDL, driver writes and server-expression/client reads for scale8/9, 1582 dates/BCE/year0, TIME24 and TIME>6, TLTZ scale6/7. CAST conversions are explicitly marked characterization and never substituted for exact typed-write oracle. A successful expression's actual server fields/text and separately observed column scale own the read contract even when CAST changed the request. Independent server TLTZ seed rows test W read refusal separately from W write refusal. Ordinary DATE, TIME(6), and TIME(6) WITH TIME ZONE server seeds additionally expose real CType/scale, cached cell payload length/hash and result format for the DATE3/TIME5/TIME_TZ7 handoff; an observed shape is not a guessed nominal layout. A driver failure is not labeled server unsupported. Existing Builder restrictions stay in force: no nondefault timezone, DbTimeToTimeSpan, BDTA or IntervalMode. TLTZ cross-session timezone is closed because no verified allowed path establishes driver/server session agreement; ordinary main gates continue.

Before any DDL, every connection confirms configured TEST identity, actual USER/schema, exact shared 8.1.5.60 or TLS 8.1.4.6, and an allowlisted physical encoding with no override. The base six-digit table is created independently; subsequent seven-digit DDL failures are recorded and cannot prevent six-digit probing. A nonce owned table is checked absent and recorded with identity/profile/package hashes in a CreateNew ownership manifest before CREATE. The same atomic CREATE includes a nonce-specific owner-marker column whose VARCHAR default contains the full 128-bit nonce; recovery verifies both its shortened name and exact full default, so changing only the manifest nonce suffix cannot claim another object. Creation states distinguish reserved/inflight/confirmed/known failure. Known create failure never authorizes DROP; lost acknowledgement requires an exact marker match in the dedicated schema, and a missing/mismatched marker retains the recovery manifest without guessing ownership. DDL is assumed implicitly committed. Every lane uses finally to DROP only that exact owned table and confirms absence on a new TEST connection. The runner always performs an additional bounded cleanup process from a strictly validated manifest, including after hard deadline; either primary failure or independent cleanup failure stops subsequent DB lanes while retaining both exit outcomes and the exact recovery manifest; the cleanup command accepts no arbitrary table name and validates nonce/profile/package/manifest identity. If cleanup fails, the precise ownership manifest remains for recovery; no whole-schema cleanup is performed.

`--gate characterization` accepts only a complete baseline characterization, verified ordinary O→W oracle, profiles and cleanup. It does not require baseline W to satisfy future write/rejection rules. `--gate candidate` requires a candidate identity and `--capabilities` runner input: a final root-approved capability manifest pinned to `source_commit` and `w_package_sha256`. Capabilities additionally bind exact `source_manifest_sha256`, producer `source_commit` and `w_package_sha256`. Its `profiles.shared` / `profiles.tls` entries contain exact `server_version`, `root_approved: true`, an `evidence_id`, boolean `seven_write`, integer `write_scales`, separate `tltz_read/write: false`, local/UTC ticks min/max and offset minutes min/max. Root-approved `verified_unsupported_error_numbers` can close individually identified server responses; arbitrary DmException, timeout or unverified driver error cannot establish server unsupported. These are explicit reviewed inputs, not generated approval. Shared must approve seven digits; TLS must retain seven-digit refusal until root explicitly approves evidence for that profile. Candidate gates enforce six-digit exactness, approved seven-digit writes, closed Scale7 NotSupported even for whole microseconds, independent server evidence, W exact getters, nonzero Precision rejection, stable inferred binding, and approved/closed higher-scale writes. For already legal higher-scale reads it checks exact GetString and CLR tick/refusal semantics separately. Extended capability conclusions remain individual case observations; profile acceptance is never whole TP-06/EF/release acceptance. Missing lanes, cases, identities, profile checks or final absence cannot pass. The TLS candidate gate uses W + server oracle and explicitly does not assert O TLS acceptance.

Python's shared contracts loader and the executable recursively reject duplicate JSON keys. Authoritative schema/count/code/scale/ticks fields exclude bool-as-integer and unknown profiles/lanes. Open/identity/profile/timeout/transport failures terminate the lane and trigger exact cleanup; safe failure records distinguish user rejection, verified server response, unverified driver error and CLR constructor preconditions. No exception message is used as server-capability evidence.
