# TP06 same-package supplemental acceptance

This tool implements the frozen [G1/G2/G3 coverage design](../../docs/implementation/temporal-native/TP06-coverage-audit.md). It supplements the unchanged complete v11 shared/TLS candidate gates. Its result does not establish full temporal, EF or release acceptance.

The only candidate is `W.DamengProvider 0.1.0-temporal.20261008144915`: package `da8349a2c3f49a97ae71baa5e1b9a694ca820dd21dea4faa7cf4006b0007142d`, DLL `843710bec351b65aa075cd917bb352a525fdbc6e1a6e1396eeaae46dc8946980`, MVID `aa23e673-957c-4b1e-bf0f-291ff60077e6`. Product manifest/archive and both profile capabilities remain pinned to the frozen package preparation. The project uses exact PackageReference assets, not a project/DLL reference. The executable checks actual loaded assemblies, runtime deps, source/archive/capability bytes and tool input hashes before Configure/Open. It verifies actual TEST user/schema and the physical profile immediately after every Open, before any test DDL/DML. The runner checks archive/package identity using byte-pinned, reviewed v11 Python helpers copied into its private build.

`case-manifest.json` defines the exact required cases and integer inputs; independent `contracts.py` reconstructs its policy with handwritten constants. The consumer executes that manifest, while `validate.py` evaluates real reports independently. Raw fields come from the actual ordinary result cache before temporal getters. Expected values never call product formatters/encoders. Server text is obtained from actual server expressions; an unknown interval CAST text remains a failed observation, rather than being accepted as a new server capability.

G1 covers caller-direct synchronous INSERT, PrepareAsync UPDATE with CommitAsync, asynchronous UPDATE/RollbackAsync, exact rejection with same logical connection recovery and fresh unchanged value, asynchronous ordinary/SequentialAccess rows (one getter per scalar alias in SequentialAccess), changed result metadata via NextResultAsync, and a bounded 128-row ordinary VARCHAR fixture that must observe actual FETCH opcode7. BufPrefetch stays default. G2 covers representative explicit DbType/profile-Scale declarations with a single explicit Prepare followed by value-only reuse (the unchanged v11 declaration matrix carries inferred-default coverage), automatic reprepare after actual Scale changes, dual-declaration clone isolation, ResetDbType, and an actual new connection. Setter receipts distinguish value-only and metadata mutations. Leading control/target execute PrepareAsync/ExecuteNonQueryAsync so the existing read-only AfterFrameSent hook provides actual business-send receipts, separate from AfterFrame response receipts. Both hooks are restored; callbacks read numeric/binding state only and never issue SQL. G3 covers native DateOnly/TIME TimeOnly/TimeSpan parameter writes and typed reads, exact extrema, NULL, six-digit fraction refusal, and DAY(2) leading attribution per the [source addendum](../../docs/implementation/temporal-native/TP06-coverage-addendum.md) and [observability addendum](../../docs/implementation/temporal-native/TP06-observability-addendum.md). Fixed100 writer failures preserve the actual pre-execute raw describe and separate 99-day control binding; unpublished current bindings stay null. The exact advisory placeholder branch records independent literal controls and exits pending until its actual server error number is explicitly reviewed. No default server error approval exists. Ordinary interval default mapping is DmIntervalDT for DAY(9), TimeSpan for DAY(2); no alternate interval/TIME mode is enabled.

Reviewed safety functions copied from v11 are identified in `Safety.cs`. Every opened connection verifies TEST user/schema and physical profile. One new 32-hex nonce table has a nonce default marker. CREATE acknowledgement state is persisted before CREATE; cleanup validates exact identity/profile/package/nonce and actual marker. It never drops a present foreign/unconfirmed/known-failure table. Primary finally cleanup and a separate bounded cleanup process independently record fresh actual catalog COUNT0 and TEST identities. Primary failure or cleanup failure blocks success and retains the recovery ownership manifest. DDL is outside transaction tests and has no rollback claim.

Only Low runs these commands, after the new tool is frozen and reviewed. Python contract tests are expected-only; they cannot establish DB/package-runtime acceptance:


Use the prepared identities/feed/source/archive/root-approved capabilities paths from the same TP06 package. All output directories must be new. The runner removes inherited DAMENG variables for builds and invokes the original TEST-only wrapper exclusively for real runs:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/TemporalCandidateAcceptance/run.py \
  --identities <prepared-identities.json> --feed <prepared-feed> \
  --source-manifest <frozen-product-manifest.json> --source-archive <frozen-product-source.tar> \
  --capabilities <root-approved-capabilities.json> --repo <original-repository> \
  --profile shared --output <new-private-output> --offline-only
```

This first restores/builds with SDK10.0.401, a writable DOTNET_CLI_HOME, telemetry/first-run disabled, single-node/no servers/no shared compilation. Then actual C# offline safety contracts run before any DAMENG environment access. A later approved DB window uses a different output directory, omits `--offline-only`, and runs shared then TLS serially. The native executable CLI is `run|cleanup identities feed profile supplemental originalRepo ownership report manifest`; it is not an arbitrary-table cleanup interface. Deadline is60..1800 seconds, default1200; independent cleanup is90 seconds. Child stdout/stderr are discarded. Safe reports contain only allowlisted types/numbers, synthetic temporal values, safe fixed IDs and public SHA/MVID; raw exception messages, SQL, credentials and driver objects are never serialized.

After a complete run, Low invokes the independently frozen validator on the same output directory:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 <new-private-output>/frozen-input/validate.py <new-private-output> --output <new-private-output>/validation.json
```

Missing/duplicate case, wrong package/source/tool/profile, impossible receipt, skipped operation, unknown error, nonordinary cache, missing actual FETCH/more-result proof, altered clone, any timeout, or nonzero cleanup state fails closed. `supplemental.json`, `.cleanup.json`, `.ownership.json`, runner/assets/lock/deps/runtime/source/archive and policy/dependency hashes are all retained separately. The initial implementation has not been built, tested or run against the database by its coding agent.
